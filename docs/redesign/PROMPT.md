# البرومت النهائي — إعادة تصميم واجهة تطبيق «ميزانيتي»

> **طريقة الاستخدام:** الصق هذا الملف كامل في الأداة اللي بنيت فيها المشروع، وقل لها:
> «نفّذ هذا المستند على المشروع الحالي مرحلة مرحلة، وبعد كل مرحلة اعرض عليّ الملفات المتغيّرة قبل ما تنتقل للي بعدها.»
>
> الملف مقسّم على **٨ مراحل مرتّبة حسب الأولوية**. تقدر تنفّذ المرحلة ١ و٢ لحالها وتشوف الفرق فوراً.

---

## ٠ · السياق والهدف

**المشروع:** تطبيق ويب لتتبع المصاريف اليومية وإدارة الميزانية الشهرية.
**التقنيات الحالية:** Laravel 12 + Inertia.js + Svelte 5 (Runes) + TypeScript + Tailwind CSS v4 + shadcn-svelte + lucide-svelte.
**اللغة والاتجاه:** عربي، RTL كامل.
**العملة:** الريال السعودي، والمبالغ مخزّنة في قاعدة البيانات بـ **الهللات (integer)**.

**الهدف من هذا التعديل:**
التطبيق حالياً عبارة عن ٦ صفحات منفصلة، كل وحدة جزيرة لحالها، والمستخدم الجديد يدخل على لوحة تحكم فاضية وما يدري من وين يبدأ.
المطلوب تحويله إلى **مسار مالي واحد متصل**:

> يُدخل دخله الكامل ← يسجّل التزاماته الثابتة (فواتير + أقساط + ادخار) ← يوزّع الباقي على فئات الميزانية ← يشوف في لوحة التحكم **صورة كاملة**: كم دخله، كم محجوز، كم صرف، **وكم باقي له فعلاً**.

**مبدأ التصميم الحاكم:** هادئ، مرتّب، احترافي، بسيط لأي مستخدم. لا تعقيد، ولا زخرفة بلا معنى. كل لون في الواجهة يحمل معنى.

## ١ · نظام التصميم (Design System) — نفّذ هذا أولاً

### ١.١ الخط العربي — **إصلاح إلزامي**

المشروع حالياً يستخدم `Instrument Sans` وهو **لا يدعم الحروف العربية إطلاقاً**، فالنص العربي ينزل على خط النظام الاحتياطي. هذا السبب الأول لإحساس «الواجهة ناقصة شي».

في `resources/css/app.css` استبدل `--font-sans` بالكامل:

```css
@theme inline {
  --font-sans: "IBM Plex Sans Arabic", "Instrument Sans", ui-sans-serif, system-ui, sans-serif;
}
```

وأضف في `resources/views/app.blade.php` داخل `<head>`:

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=IBM+Plex+Sans+Arabic:wght@400;500;600;700&display=swap" rel="stylesheet">
```

> **بديل مقبول:** `Rubik` أو `Noto Sans Arabic`. تجنّب `Cairo` لأن أرقامه أقل وضوحاً في الجداول.

**قواعد استخدام اللون — إلزامية:**

1. **لون واحد فقط للعلامة** (`--primary`). يُستخدم للأزرار الأساسية، الروابط، حلقة التركيز، وعنصر التنقل النشط. **لا يُستخدم في أي رسم بياني.**
2. **ألوان الحالة محجوزة:** أخضر = آمن، أصفر = اقترب من الحد، أحمر = تجاوز. **لا تستخدمها لأي غرض تزييني.**
3. **ترتيب البالتة الفئوية ثابت ولا يُدوَّر.** الفئة رقم ٨ لا تأخذ لوناً مولَّداً — تنطوي تحت «أخرى».
4. **اللون يتبع الكيان، لا ترتيبه.** فلتر يغيّر عدد الفئات المعروضة يجب ألا يعيد تلوين الباقية.
5. **النص لا يلبس لون السلسلة أبداً.** الأرقام والعناوين والمفاتيح تبقى بألوان الحبر (`foreground` / `muted-foreground`)، واللون يحمله المربّع أو الأيقونة المجاورة فقط.
6. **حالة اللون لا تُنقل باللون وحده** — دائماً أيقونة + نص («تجاوزت»، «اقترب»، «آمن»).

### ١.٣ الأيقونات — **إصلاح إلزامي**

**احذف كل استخدام للإيموجي في الواجهة.** حالياً `Budgets.svelte` و `Installments.svelte` و `Savings.svelte` تستخدم إيموجي (`🍔 🚗 📦 💰`) وهو:
غير متسق بين الأجهزة، لا يتلوّن مع الثيم، ويبدو غير احترافي.

**البديل المعتمد:** أيقونة `lucide-svelte` داخل **دائرة/مربّع مستدير بلون الفئة بشفافية 12%**، والأيقونة نفسها بلون الفئة الكامل.

```svelte
<span
  class="flex size-8 items-center justify-center rounded-[9px]"
  style="background:{category.color}1f; color:{category.color}"
>
  <CategoryIcon name={category.icon} class="size-4" />
</span>
```

**أنشئ ملف `resources/js/lib/category-icons.ts`** يحتوي خريطة ثابتة من اسم الفئة إلى مكوّن lucide:

| ترفيه | `gamepad-2` |
| فواتير | `zap` |
| صحة | `heart-pulse` |
| تعليم | `graduation-cap` |
| سكن / إيجار | `home` |

**عند إنشاء فئة مخصصة:** اعرض على المستخدم **شبكة أيقونات lucide** (٢٤ أيقونة) بدل شبكة الإيموجي الحالية — نفس التفاعل، أيقونات بدل رموز. غيّر عمود `categories.icon` ليخزّن اسم أيقونة lucide (مثل `"utensils"`) بدل رمز الإيموجي، واكتب migration لتحويل القيم القديمة.

### ١.٤ قواعد RTL — إصلاحات مطلوبة

المشروع فيه استخدامات اتجاهية مثبّتة تنكسر في RTL. ابحث واستبدل في كل الملفات:

| احذف | استخدم بدلها |
|---|---|
| `bg-gradient-to-l` / `bg-gradient-to-r` | `bg-linear-to-s` (نحو البداية) أو احذف التدرّج كلياً |
| `left-0` / `right-0` | `start-0` / `end-0` |
| `ml-*` / `mr-*` | `ms-*` / `me-*` |
| `pl-*` / `pr-*` | `ps-*` / `pe-*` |
| `text-right` (كافتراضي) | `text-start` |
| `text-left` | `text-end` |
| `rounded-l-*` / `rounded-r-*` | `rounded-s-*` / `rounded-e-*` |
| `border-l` / `border-r` | `border-s` / `border-e` |

أمثلة موجودة فعلياً تحتاج إصلاح: `Dashboard.svelte` سطر 199 (`bg-gradient-to-l`) وسطر 310 (`absolute left-0`)، و `Budgets.svelte` سطر 200.

### ١.٥ الأرقام والتواريخ

**أنشئ `resources/js/lib/format.ts`** واحذف النسخ المكررة من `formatCurrency` الموجودة في **خمس صفحات** (`Dashboard`, `Budgets`, `Income`, `Expenses`, `Bills`, `Installments`, `Savings`):

```ts
const NUM = new Intl.NumberFormat('ar-SA-u-nu-latn', {
  minimumFractionDigits: 0,
  maximumFractionDigits: 2,
});

/** المدخل بالهللات، المخرج نص معروض */
export function formatCurrency(halalas: number, opts?: { compact?: boolean }): string {
  const riyals = halalas / 100;
  if (opts?.compact && Math.abs(riyals) >= 1000) {
    return NUM.format(Math.round(riyals / 100) / 10) + ' ألف ر.س';
  }
  return NUM.format(riyals) + ' ر.س';
}

export function formatDate(iso: string): string {
  return new Intl.DateTimeFormat('ar-SA-u-ca-gregory-nu-latn', {
    day: 'numeric', month: 'long',
  }).format(new Date(iso));
}

export function formatPercent(n: number): string {
  return NUM.format(Math.round(n)) + '٪';
}
```

**مهم:** استخدم `-u-nu-latn` لفرض **الأرقام اللاتينية (1234)**، لأن الأرقام الهندية (١٢٣٤) أصعب في القراءة السريعة داخل الجداول المالية. واستخدم `-u-ca-gregory` لفرض **التقويم الميلادي**، لأن `ar-SA` يعطي التقويم الهجري افتراضياً وهذا يكسر تطابق التواريخ مع كشف الحساب البنكي.

**كل رقم في جدول أو عمود يجب أن يحمل `tabular-nums`.** الأرقام الكبيرة المستقلة (الرقم البطل) تستخدم الأرقام النسبية العادية.

## ٢ · البنية والتنقل

### ٢.١ إعادة تنظيم الشريط الجانبي — `resources/js/components/AppSidebar.svelte`

الترتيب الحالي غير منطقي (لوحة التحكم في المركز السابع)، والقائمة مسطّحة بثمانية عناصر بلا تجميع.

**استبدلها بثلاث مجموعات + مجموعة رابعة للمساعد:**

```
نظرة عامة
  └── لوحة التحكم            /dashboard        (LayoutGrid)

فلوسي
  ├── الدخل                  /income           (TrendingUp)
  ├── الميزانية              /budgets          (Target)
  └── المصاريف               /expenses         (ArrowRightLeft)

التزاماتي
  ├── الفواتير               /bills            (ReceiptText)   + شارة عدد المستحق
  ├── الأقساط                /installments     (CreditCard)
  └── الادخار                /savings          (PiggyBank)

أدوات
  ├── التقارير               /reports          (FileBarChart)
  └── المساعد الذكي          /assistant        (Sparkles)      + شارة "تجريبي"
```

**تفاصيل:**

- عنوان كل مجموعة: `text-[11px] text-muted-foreground` بمسافة `pt-3.5 pb-1.5 px-3`.
- العنصر النشط: `bg-accent text-accent-foreground font-semibold` — **لا تستخدم شريطاً جانبياً ملوّناً**، الخلفية كافية.
- **شارة الفواتير:** عدد الفواتير المستحقة خلال ٧ أيام، بخلفية `--destructive` ونص أبيض، `text-[10px] rounded-full px-1.5`. تُمرَّر من الباك إند عبر Inertia shared props.
- **احذف نهائياً** عنصر «المساعد الذكي» الحالي بـ `href="#"` — الرابط الميت في التنقل يضرّ الثقة. استبدله بالمسار الفعلي `/assistant` (المرحلة ٧).
- تحت اسم التطبيق في الهيدر، اعرض **الشهر الحالي** بخط صغير (`أغسطس 2026`) كسياق دائم.

### ٢.٢ زر الإضافة السريعة العائم (FAB) — مكوّن جديد

**المشكلة:** لإضافة مصروف، المستخدم لازم ينتقل لصفحة المصاريف ثم يفتح مودال. هذا احتكاك في **أكثر إجراء يتكرر يومياً**.

**أنشئ `resources/js/components/QuickAddFab.svelte`** واستدعِه من `AppSidebarLayout.svelte` بحيث يظهر في **كل الصفحات**:

- زر دائري `size-14` ثابت في `bottom-6 start-6` (بداية السطر = يمين في RTL... **تنبيه:** ضعه في `inset-inline-start` أي **يسار الشاشة في RTL** حتى لا يغطي محتوى الجداول).
- بالضغط: تنفتح لأعلى ٤ خيارات بحركة `stagger` بسيطة (تأخير 30ms بين كل عنصر):
  **مصروف** (أزرق) · **دخل** (أخضر) · **فاتورة** (بنفسجي) · **ادخار** (أخضر مائي).
- أيقونة `+` تدور 45° لتصير `×` عند الفتح.
- كل خيار يفتح **نفس المودال المشترك** المستخدم في صفحته الأصلية (لا تكرّر النماذج).
- يُغلق بـ `Esc` أو بالنقر خارجه.
- **إخفاء تلقائي** أثناء فتح أي مودال آخر.

### ٢.٣ المسارات الجديدة — `routes/web.php`

## ٣ · معالج الإعداد الأول (Onboarding Wizard) — **شاشة جديدة كلياً**

**لماذا:** أهم فجوة في التطبيق. المستخدم الجديد حالياً يدخل لوحة فاضية بلا اتجاه. هذا المعالج يملأ التطبيق ببيانات حقيقية في أقل من دقيقتين، ويجعل كل الأرقام في اللوحة ذات معنى من اللحظة الأولى.

**المسار:** بعد التسجيل مباشرة، **قبل** لوحة التحكم.
**التخطيط:** بطاقة واحدة بعرض `max-w-2xl` في منتصف الشاشة، بدون شريط جانبي، على خلفية `--background`.

### شريط التقدّم (أعلى البطاقة)

ثلاث خطوات أفقية مرقّمة، متصلة بخط. الخطوة المكتملة: دائرة خضراء بعلامة صح. الحالية: دائرة بلون العلامة. القادمة: دائرة رمادية بحدود.

### الخطوة ١ — «كم دخلك الشهري؟»

- **حقل مبلغ كبير** (`text-2xl font-semibold`) بلاحقة `ر.س` داخل الحقل خلف فاصل رأسي.
- سؤال: «هل هو راتب ثابت كل شهر؟» → مفتاح `Switch`. لو مفعّل، يُنشأ سجل في `recurring_transactions` تلقائياً.
- زر «+ إضافة مصدر دخل آخر» يضيف صفاً جديداً (عمل حر، إيجار عقار، …).
- في الأسفل: «إجمالي دخلك الشهري: **X ر.س**» يتحدّث لحظياً.

### الخطوة ٢ — «وش التزاماتك الثابتة كل شهر؟»

- **رقائق (chips)** جاهزة قابلة للاختيار المتعدّد، كل واحدة بأيقونة lucide:
  كهرباء وماء · إيجار · إنترنت وجوال · تأمين · قسط سيارة · قسط جهاز · اشتراكات · + التزام آخر
- عند اختيار رقاقة، يظهر لها **صف بمنزلق (slider) + حقل رقمي** لتحديد المبلغ الشهري. المنزلق أسرع من الكتابة على الجوال، والحقل الرقمي للدقة.
- **حقل مستقل:** «يوم استحقاق راتبك» → رقائق `25 / 27 / آخر يوم / يوم آخر…`
  هذا الحقل هو ما يجعل حساب «المتبقي يومياً» والتنبيهات الاستباقية ممكناً.
- **صندوق تنبيه معلوماتي** بلون العلامة الفاتح يشرح: «هذي الخطوة هي اللي تخلي رقم *المتبقي لك* في لوحة التحكم واقعي.»
- عند الحفظ: تُنشأ سجلات فعلية في جداول `bills` و `installments`.

### الخطوة ٣ — «وزّع الباقي على فئاتك»

- في الأعلى: بطاقة تعرض **«الباقي للتوزيع: X ر.س»** (الدخل − الالتزامات) ويتناقص مع كل تخصيص.
- قائمة الفئات الافتراضية، كل صف: أيقونة ملوّنة + الاسم + منزلق + المبلغ.
- **زر «اقترح توزيعاً تلقائياً»** يوزّع حسب نسب واقعية (طعام 30٪، مواصلات 15٪، ترفيه 10٪، صحة 10٪، أخرى 10٪، والباقي ادخار). هذا يقلّل الاحتكاك بشكل هائل لمن لا يعرف من أين يبدأ.
- **شريط تدفق مباشر** أسفل القائمة يعرض التوزيع بصرياً وهو يُبنى.
- **حالة الخطأ:** إذا تجاوز مجموع التخصيص المبلغ المتاح، يتحوّل الشريط للأحمر مع رسالة «تجاوزت المتاح بـ X ر.س» ويتعطّل زر الإنهاء.

### التذييل (كل الخطوات)

- يسار: زر نصّي خفيف «تخطّي الآن — أكمل من اللوحة لاحقاً».
- يمين: `رجوع` (ثانوي) + `التالي` (أساسي).
- **إذا تخطّى المستخدم:** تظهر في أعلى لوحة التحكم بطاقة «أكمل إعدادك» فيها الخطوات الثلاث مع شريط تقدّم، وتختفي تلقائياً عند اكتمالها.

2. **فلتر الشهر الصوري** (`selectedMonth` + `showMonthDropdown`، الأسطر 191, 301–324). حالياً يغيّر متغيّراً محلياً فقط ولا يجلب أي بيانات — وعد كاذب للمستخدم.
3. **بطاقة الرسالة التحفيزية** (`motivationalStatus`، الأسطر 474–503). تأخذ مساحة كبيرة جداً مقابل معلومة يعرفها المستخدم أصلاً من ألوان الفئات. **انقل مضمونها إلى سطر واحد** تحت الرقم البطل.
4. **دالة `donutPath` اليدوية** — استبدلها بأسلوب `stroke-dasharray` (أبسط، أدق، ويدعم التدوير والحواف).

### ٤.٢ القسم ١ — «بطاقة القصة المالية» (الأهم)

بطاقة واحدة بحواف `rounded-[22px]` تحتوي على كل ما طلبته: الدخل، الميزانية، المصروف، والمتبقي.

**الصف العلوي (من اليمين لليسار):**

| العنصر | المحتوى |
|---|---|
| **الرقم البطل** | «المتبقي لك للصرف» — `text-4xl font-semibold`. تحته سطر واحد: «تقدر تصرف **X ر.س يومياً** وتوصل آخر الشهر بأمان» |
| فاصل رأسي | خط `1px` بلون `border` |
| **دخلك** | مبلغ `text-lg font-semibold` |
| **محجوز (التزامات)** | مبلغ — فواتير + أقساط + ادخار |
| **صرفت هذا الشهر** | مبلغ |
| **بطاقة جانبية** | «متوسط صرفك اليومي: X ر.س» + سطر حالة أخضر/أحمر: «أقل من الحد الآمن ✓» أو «أعلى من الحد الآمن ⚠» |

**المعادلات:**

```
المحجوز        = الفواتير غير المدفوعة هذا الشهر + الأقساط الشهرية + تحويلات الادخار المجدولة
المتبقي لك     = إجمالي الدخل − المحجوز − المصاريف المسجّلة هذا الشهر
الأيام المتبقية = أيام حتى يوم استحقاق الراتب القادم
الحد اليومي الآمن = المتبقي لك ÷ الأيام المتبقية
```

**قواعد العرض:**
- إذا كان «المتبقي لك» سالباً: الرقم بلون `--destructive`، والسطر تحته يصير «تجاوزت دخلك بـ X ر.س هذا الشهر».
- إذا كانت `الأيام المتبقية = 0` (يوم الراتب): اعرض «راتبك اليوم 🎉» بدل الحد اليومي.

**الصف السفلي — شريط التدفق (Flow Bar):**

شريط أفقي واحد بارتفاع `34px` و `rounded-[10px]`، مقسّم بنسب الدخل، **بفاصل 2px بلون السطح بين كل قطعة وأختها**:

| القطعة | اللون |
|---|---|
| فواتير | `--chart-7` بنفسجي |
| أقساط | `--chart-2` برتقالي |
| ادخار | `--chart-3` أخضر مائي |
| مصاريف | `--chart-1` أزرق |
| **متبقي لك** | خطوط مائلة 135° على خلفية السطح، بحدود متقطّعة — **يقرأ بصرياً كـ «فراغ متاح» لا كالتزام** |

- نسبة كل قطعة مكتوبة داخلها إذا كان عرضها يسمح (`≥ 8%`)، وإلا فقط في مفتاح الرسم.
- `title` على كل قطعة بالاسم والمبلغ.
- تحت الشريط: **مفتاح رسم بالمبالغ الفعلية** — ليس بالنسب فقط، لأن ثلاثة من ألوان البالتة تحت 3:1 تباين على السطح الفاتح، والتسمية المباشرة هي المعالجة الإلزامية لذلك.
- سطر توضيحي صغير: «شريط واحد يقرأ من اليمين لليسار: من وين دخل الراتب، ووين راح، وكم بقي.»

### ٤.٣ القسم ٢ — التقويم المالي (**عنصر جديد**)

شريط أفقي بالأيام الأربعة عشر القادمة. كل يوم بطاقة صغيرة `w-[46px]`: اسم اليوم مختصر + الرقم + **نقاط ملوّنة** أسفله ترمز للأحداث المالية.

- اليوم الحالي: حدود بلون العلامة + حلقة `ring-2` خفيفة.
- النقاط: راتب (أخضر) · فاتورة مستحقة (بنفسجي) · قسط (برتقالي) · تحويل ادخار (أخضر مائي).
- مفتاح رسم صغير تحت الشريط.
- بالنقر على يوم: تظهر قائمة منسدلة بأحداثه مع أزرار إجراء («تم الدفع»).
- رابط «عرض الشهر كامل» يفتح تقويماً شهرياً كامل.

**القيمة:** يمنع أكثر مفاجأة مزعجة في إدارة الميزانية — «انسحب مني قسط ما كنت متوقعه».

### ٤.٤ القسم ٣ — أربع بطاقات مختصرة

`grid-cols-4` (تصير `grid-cols-2` على الجوال). كل بطاقة: التسمية + أيقونة في مربّع ملوّن `size-8 rounded-[9px]` + المبلغ + سطر سياق.

| البطاقة | السطر السياقي |
|---|---|
| الدخل | «راتب + دخل إضافي» |
| المصاريف | مقارنة بالشهر الماضي: «أقل 12٪ عن الشهر الماضي» بلون أخضر (أو أعلى بالأحمر) |
| المحجوز | «5 فواتير · قسطين» |
| الادخار | «6٪ من دخلك · الهدف 10٪» |

> **قلّلها من خمس بطاقات إلى أربع** — الخامسة الحالية (الفواتير المستحقة) مكرّرة مع «المحجوز» ومع التقويم.

### ٤.٥ القسم ٤ — رسمان جنباً إلى جنب

**(أ) «وين راحت مصاريفك؟» — رسم دائري مجوّف**

- `stroke-dasharray` على دوائر SVG بنصف قطر موحّد، بفاصل 2px بين القطع.
- في المنتصف: **إجمالي المصروف** + «ر.س».
- **بجانبه قائمة مباشرة** بكل فئة: أيقونة ملوّنة + الاسم + **المبلغ** + النسبة. القائمة **إلزامية** (ليست خياراً) لأنها البديل عن التباين المنخفض لبعض الألوان.
- **حد أقصى ٧ فئات معروضة**؛ الباقي ينطوي تحت «أخرى» بلون رمادي.
- عند تمرير الفأرة على صف: تُبرز القطعة المقابلة في الدائرة، والعكس.
- رابط «جدول البيانات» يعرض نفس الأرقام كجدول HTML — لقارئات الشاشة وللطباعة.

**(ب) «الدخل مقابل المصاريف — ٦ أشهر» — أعمدة مزدوجة**

- **٦ أشهر فقط، لا ١٢** — الاثنا عشر عموداً الحالية مزدحمة وغير مقروءة على الجوال.
- عمودان لكل شهر بعرض `11px`، `rounded-t-[4px]`، بفاصل 2px.
- الأشهر السابقة بشفافية `42%`، والشهر الحالي **بلون كامل** واسمه `font-semibold`.
- **محور واحد فقط.** ممنوع منعاً باتاً استخدام محورين رأسيين مختلفين.
- مفتاح رسم أسفل: دخل (أخضر مائي) · مصاريف (أزرق) · «الشهر الحالي بلون كامل».
- عند تمرير الفأرة: `tooltip` بالشهر والمبلغين والفرق بينهما.
- رابط «آخر 12 شهر» يفتح نفس الرسم موسّعاً.

### ٤.٦ القسم ٥ — «ميزانيتك حسب الفئة»

`grid-cols-2` من الصفوف المدمجة (وليس بطاقات كاملة الارتفاع — أوفر للمساحة):

كل صف: أيقونة ملوّنة + اسم الفئة + **شارة حالة** + شريط تقدّم + سطر أرقام.

| الحالة | الشرط | اللون | الشارة |
|---|---|---|---|
| آمن | < 70٪ | لون الفئة نفسه | `✓ آمن` أخضر |
| اقترب | 70–90٪ | `--warning` | `⚠ اقترب` كهرماني |
| تجاوزت | > 100٪ | `--destructive` | `⚠ تجاوزت` أحمر |

- السطر السفلي: «321 من 500 ر.س» ← يسار: «باقي 179» أو «تجاوز 32» بالأحمر.
- **شريط التقدّم لا يتجاوز 100٪ بصرياً**؛ التجاوز يُنقل بالشارة والنص الأحمر.
- رابط في رأس البطاقة: «تعديل الميزانية →».

### ٤.٧ القسم ٦ — آخر المعاملات

- الجدول الحالي جيد، لكن أضف: **أيقونة الفئة الملوّنة** بجانب كل وصف، وعلامة `−` / `+` قبل المبلغ بلون `destructive` / `success-text`.
- **على الجوال:** الجدول يتحوّل إلى **بطاقات مكدّسة** (لا تمرير أفقي). استخدم `hidden md:table` للجدول و `md:hidden` لقائمة البطاقات.
- **حالة فارغة إلزامية:** أيقونة + «ما فيه معاملات بعد» + زر «أضف أول مصروف».

### ٤.٨ حالات اللوحة

| الحالة | ماذا يُعرض |
|---|---|
| **لا بيانات إطلاقاً** | حالة فارغة كبيرة في منتصف الصفحة: أيقونة + «ابدأ بإعداد ميزانيتك» + زر يقود لمعالج الإعداد. **لا تعرض بطاقات بأصفار.** |
| **إعداد ناقص** | بطاقة «أكمل إعدادك» بثلاث خطوات وشريط تقدّم، أعلى اللوحة. |
| **جارٍ التحميل** | هياكل عظمية (`skeleton`) بنفس أبعاد البطاقات الحقيقية — لا مؤشّر دوّار. |

- زر «تعليم الكل كمقروء» في رأس القائمة.
- **حدّ أقصى 5 تنبيهات نشطة** في وقت واحد — الإفراط يجعل المستخدم يتجاهلها كلها.
- **إعدادات التنبيهات** في `settings/`: يتحكّم المستخدم في تفعيل كل نوع.
- **المرحلة الثانية (اختياري):** إرسال نفس التنبيهات بالبريد الإلكتروني عبر Laravel Notifications + مهمة مجدولة يومية.

**الباك إند:** جدول `notifications` (Laravel المدمج)، مع `Job` مجدول يومياً يفحص الشروط وينشئ التنبيهات.

## ٧ · صفحة التقارير `/reports` (**صفحة جديدة**)

**التخطيط:**

1. **شريط تحكّم علوي:** نوع التقرير (شهري / ربع سنوي / سنوي / نطاق مخصّص) + منتقي الفترة + أزرار التصدير.
2. **بطاقة ملخّص:** إجمالي الدخل · إجمالي المصاريف · صافي الادخار · نسبة الادخار — كل رقم مع **مقارنة بالفترة السابقة** (سهم ونسبة).
3. **رسم اتجاه:** الدخل والمصاريف عبر الفترة (خطّي).
4. **جدول تفصيلي بالفئة:** الفئة · المخصّص · المصروف · الفرق · النسبة، **مع إمكانية الترتيب** بأي عمود.
5. **أعلى 5 مصاريف مفردة** في الفترة.
6. **مقارنة شهرية:** جدول الفئات × الأشهر، مع تظليل حراري خفيف (تدرّج أزرق أحادي اللون — **ليس قوس قزح**).

**التصدير:**
- **PDF:** تصميم مطبوع نظيف بالأبيض والأسود مع الشعار والفترة والتاريخ. استخدم `barryvdh/laravel-dompdf`. قالب Blade مخصّص للطباعة (لا لقطة شاشة للصفحة).
- **Excel:** ورقتان — ملخّص، وقائمة معاملات خام. استخدم `maatwebsite/excel`.

## ٨ · المساعد الذكي `/assistant` (**هيكل جاهز**)

> المطلوب في هذه المرحلة: **بناء الواجهة الكاملة فقط**، مع تجهيز نقطة الاتصال بالخدمة. المنطق الذكي سيُضاف لاحقاً.

**التخطيط:** واجهة محادثة بعرض `max-w-3xl` في منتصف الصفحة.

- **حالة الترحيب:** أيقونة + «اسألني أي شي عن ميزانيتك» + **٤ رقائق اقتراحات جاهزة**:
  «كم صرفت على الطعام هالشهر؟» · «وين أقدر أقلّل مصاريفي؟» · «هل أقدر أشتري X؟» · «سوّي لي خطة ادخار لهدف معيّن»
- **فقاعات المحادثة:** رسائل المستخدم بلون العلامة على جهة البداية، ردود المساعد بخلفية `card` مع أيقونة.
- **دعم عرض البطاقات داخل الرد:** المساعد قادر على إرجاع رسم بياني صغير أو جدول أو بطاقة رقم — لا نصّاً فقط.
- **مؤشّر الكتابة:** ثلاث نقاط متحرّكة.
- **حقل الإدخال:** ثابت أسفل الشاشة، يتمدّد تلقائياً، `Enter` للإرسال و `Shift+Enter` لسطر جديد.
- **شارة «تجريبي»** بجانب العنوان.
- **إخلاء مسؤولية بخط صغير أسفل الحقل:** «المساعد يعتمد على بياناتك المسجّلة فقط، وقد يخطئ. راجع الأرقام المهمة بنفسك.»

**الباك إند:** أنشئ `AssistantController` بمنهج `chat()` يستقبل الرسالة ويعيد استجابة مبدئية ثابتة، مع تعليق `// TODO` واضح عند نقطة استدعاء الخدمة الذكية. أنشئ جدول `assistant_messages` (user_id, role, content, created_at) لحفظ سجل المحادثة.

## ١٠ · متطلبات الباك إند

**أعمدة جديدة:**

```
users.onboarding_completed_at   timestamp nullable
users.salary_day                tinyint nullable        (1–31، أو 0 = آخر يوم)
users.currency                  varchar(3) default 'SAR'
categories.icon                 → غيّر ليخزّن اسم أيقونة lucide بدل الإيموجي (+ migration للتحويل)
budgets.is_recurring            boolean default false
budgets.rollover_enabled        boolean default false
incomes.due_day                 tinyint nullable
```

**جداول جديدة:** `notifications` (Laravel المدمج) · `assistant_messages`

**تحسينات الاستعلامات:**

- **`DashboardController` يجب أن يرجّع كل شيء في استعلام واحد مجمّع** — لا استعلام لكل قسم.
- **دعم فلتر الشهر فعلياً:** `?month=2026-08` على كل من `/dashboard` و `/expenses` و `/income`.
- **انقل الفلترة والترقيم للسيرفر** في صفحتي المصاريف والدخل.
- **أضف فهارس:** `expenses(user_id, date)` · `incomes(user_id, date)` · `bills(user_id, due_date)` · `budgets(user_id, month)`.
- **مشاركة عامة عبر Inertia (`HandleInertiaRequests`):** عدد التنبيهات غير المقروءة، وعدد الفواتير المستحقة، وحالة اكتمال الإعداد — تحتاجها كل الصفحات.

## ١١ · معايير القبول — تحقّق منها قبل الإنهاء

**التصميم البصري**
- [ ] كل النصوص العربية تظهر بخط `IBM Plex Sans Arabic` (افحص بأدوات المطوّر).
- [ ] لا يوجد أي إيموجي في أي مكان في الواجهة.
- [ ] الأحمر والأصفر والأخضر لا تظهر إلا في سياق حالة أو تحذير.
- [ ] الوضع الداكن مُختار بدرجاته الخاصة، وليس انعكاساً آلياً.
- [ ] كل حالة تحمل أيقونة ونصاً، وليس لوناً فقط.

**RTL**
- [ ] لا يوجد أي `ml-` / `mr-` / `left-` / `right-` / `text-right` في الملفات.
- [ ] كل الأيقونات الاتجاهية (الأسهم) تشير للجهة الصحيحة.
- [ ] الرسوم البيانية الزمنية تقرأ من اليمين (الأقدم) لليسار (الأحدث).

**البيانات والصدق**
- [ ] لا توجد أي بيانات وهمية مثبّتة في أي مكوّن.
- [ ] كل جدول وكل قائمة لها حالة فارغة مصمّمة.
- [ ] كل فلتر معروض يعمل فعلاً ويؤثّر على البيانات.
- [ ] كل مبلغ يُحوَّل من الهللات مرة واحدة فقط (لا ضرب مزدوج بـ 100).

**التفاعل والوصولية**
- [ ] كل المودالات تُغلق بـ `Esc`، وتحصر التركيز، وتعيده للزر عند الإغلاق.
- [ ] لا يوجد أي `svelte-ignore a11y_*` متبقٍّ.
- [ ] كل زر أيقونة له `aria-label`.
- [ ] كل حفظ أو حذف يُتبع برسالة تأكيد (toast).
- [ ] التنقّل بالكيبورد يعمل في كل الصفحات، وحلقة التركيز مرئية.

**الاستجابة**
- [ ] كل الجداول تتحوّل لبطاقات على الجوال — **صفر تمرير أفقي**.
- [ ] لوحة التحكم مقروءة بالكامل على عرض 375px.
- [ ] زر الإضافة السريعة لا يغطّي أي محتوى مهم على الجوال.

**المسار الكامل**
- [ ] مستخدم جديد → معالج الإعداد → لوحة ممتلئة بأرقام حقيقية، **دون أي شاشة فارغة محيّرة**.
- [ ] رقم «المتبقي لك» يطابق المعادلة يدوياً.
- [ ] «الحد اليومي الآمن» يتغيّر صحيحاً مع اقتراب يوم الراتب.

## ملاحظة أخيرة للأداة المنفّذة

- **لا تعيد كتابة الملفات من الصفر.** المشروع الحالي بنيته سليمة، والمطلوب تحسين وليس استبدال.
- **حافظ على منطق الباك إند الموجود** إلا حيث نصّ المستند صراحة على تغييره.
- **لا تُدخل مكتبة رسوم بيانية خارجية.** كل الرسوم المطلوبة (دائري مجوّف، أعمدة، شريط تدفق) تُبنى بـ SVG و CSS خالصين — أخف، وأدق في التحكم، ولا تضيف حجماً للحزمة.
- **بعد كل مرحلة، شغّل `npm run build` و `php artisan test`** وأصلح أي خطأ قبل الانتقال للمرحلة التالية.
